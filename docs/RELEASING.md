# 版の出し方（Releasing）

## 版の名前
- `package.json` の `hubVersion`（例：`V9`）が版の名前。ウィンドウの題名・データの置き場（`%APPDATA%\buildersloop-hub-v9`）・MCP のポート（17890＋9）に使われる。
- `version` は `<n>.<小さな修正>.0`。V9 は `9.0.0`、V9 の小さな修正は `9.1.0`。小さな修正では `hubVersion` を変えない（データとポートを、そのまま使う）。

## 1 版の流れ
1. **範囲を決める**：マイルストーン（例：V9）に入れる Issue を選ぶ。持ち主が決める。
2. **作る**：Issue ごとにブランチ → PR。AI のレビューと安全の検査が通れば `main` へ（外の人の PR は、持ち主が見てから）。
3. **版の準備**（PR 1 つ）：
   - `package.json` の `hubVersion` と `version` を上げる。
   - `CHANGELOG.md` に、`## V9（9.0.0）— …` の節を作り、変更点と「入れ替えるとき」の注意を書く。節の中の `- **太字**` の項目（上から 3 つ）が、前の版から入れ替えた初回の、起動時のお知らせになる。節や太字の項目が無いと、単体試験が落ちる。
   - `npm test` と `npm run e2e` が通ること。
4. **ビルド**：版ごとに、別のフォルダへ（起動中の exe は上書きできないため）。**Git Bash で**実行する（PowerShell・cmd からだと、`npx.cmd` を通るため、`|` と `^` が cmd に解釈されて壊れる）。
   ```
   npx --yes @electron/packager@20.3.0 . Buildersloop-hub-v9 --platform=win32 --arch=x64 --out=<出力先>/V9 --overwrite --asar=false --prune=true --ignore='^/(test|smoke|private|docs|[.]github)' --ignore='^/CLAUDE[.]local[.]md$' --ignore='[.]last-sessions$' --ignore='[.]log$' --ignore='^/smoke[.](err|out)$'
   ```
   - ビルドの道具は、版を固定する（いまは 20.3.0）。上げるときは、試験してから。
   - 作業フォルダには、git に入れないファイル（`private/`・`CLAUDE.local.md` など）もある。`--ignore` で exe に入れない。ビルドのあと、出力の `resources\app` に、それらが無いことを確かめる。
   - できた exe を、`E2E_EXE=<exe のパス> node test/e2e.js` で試験する。
5. **リリース**：GitHub のタグ（`v9.0.0`）とリリースを作り、CHANGELOG の該当の節を本文にする。**リリースの作成・公開は、持ち主の名指しの承認のあと。**
6. **入れ替え**：持ち主が行う。動いているセッションが終わってから、新しい版を起動する。

## 入れ替えのしくみ
- 新しい版を初めて起動すると、直前の版（無ければ、それより前の版・版のない旧版）の `hub.json` をコピーする。元のデータは変えない。
- 合言葉（トークン）とポートは、新しい版のものに作り直す。新しい版で起動・再開したセッションには、新しい版の MCP が渡る。
- 古い版も、そのまま動かせる。ただし、**同じ会話（セッション）を、2 つの Hub で同時に再開しない**（同じ記録に、同時に書いてしまう）。
- 入れ替えると、Hub の中で動いている会話も止まる。Hub の中の会話から入れ替えるときは、先に、会話の保存と、再開の手順を確かめる。
- 新しい版を初めて起動したあとで、古い版で設定を変えても、新しい版には入らない（コピーは初回だけ）。

## 引き継がれないもの（いまの限界）
- アプリ内ブラウザのログイン（Cookie）は、版ごとに別。新しい版では、ログインし直す。
- MCP の接続の秘密の値（トークンなど）。暗号化の鍵が、データのフォルダごとに違うため、新しい版では読めない。初回の起動で消し、画面に「入れ直してください」と出す。接続の定義（名前・URL など）は引き継ぐ。
- 元のデータ（hub.json）が読めない版は、飛ばして、その前の版から引き継ぐ。
