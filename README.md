# BuildersLoop Hub

[English](README.en.md) ｜ 日本語

**複数の事業（プロジェクト）を、Claude Code で並列に動かすための、Windows 用のデスクトップアプリ**です。

1 つの画面に、事業ごとの Claude Code のセッション（本物の `claude` CLI）を並べ、事業ごとにログインを分けたブラウザと、エージェント同士が協力するための MCP サーバーを持ちます。「開発」「レビュー」「セキュリティ」「運用」のように担当を分けたセッションを、まとめて起動し、互いに連絡させながら進められます。

> いまの版：**V8**（変更点は [CHANGELOG.md](CHANGELOG.md)）。ライセンス：[MIT](LICENSE)

## できること
- **事業ごとのセッション**：本物の `claude` を ConPTY で動かすターミナルを、タブ・分割で並べる。停止しても、会話の続きから再開できる（`--resume`）。
- **プリセット・プロファイル**：よく使う指示（プリセット）と、まとめて起動するセッションの一式（プロファイル）。
- **事業ごとのブラウザ**：ログイン（Cookie）を事業ごとに分けたアプリ内ブラウザ。エージェントも MCP で操作できる。
- **共同作業**：各セッションが、いま何を触っているかの一覧（`work_board`）と、作業場所の宣言（`work_claim`）。同じファイルを 2 つのセッションが触ると、競合として知らせる。
- **名簿と連絡**：各セッションに名前・役割・ID を自動で渡し、`session_send` で、ほかのセッションへ連絡できる（送信元つき）。相手が停止中なら、Hub が預かり、相手が起動したときに渡す（画面に 📨 の印）。
- **CLAUDE.md の管理**：事業ごとの指示書を、画面で編集。エージェントは「変更案」を出すだけで、反映は人が差分を見て行う。
- **組織のルール**：「使うアカウント」など、全セッションに守らせたいルールを 1 か所に書くと、すべてのセッションに渡る。
- **セットアップ担当**：Hub の設定（事業・プリセット・プロファイル）を、対話で行う専用の Claude Code。
- **MCP の接続**：GitHub・Slack などの MCP を、セッションごとに有効・無効にできる（秘密の値は Windows の暗号化で保存）。

## 安全の考え方
Hub は、エージェントに「人の代わりに承認させない」ことを最優先にしています。

- エージェント（MCP）は、**承認の言葉（y・はい・OK など）を送れません**。権限の確認が出ている画面には、Enter や文字も送れません。最初の指示や預かった連絡も、確認の画面が出ているあいだは渡しません。セッションの起動の直後（入力を受けられるようになるまで）は、エージェントからの文は預かり、Enter・キーは拒否します（あとから出る「フォルダを信頼しますか」などの確認に、答えてしまわないため）。Enter を送る直前にも、確認の画面が出ていないか、もう一度見ます（確認の画面に使われる語を含むエージェントの文は、区別できないので、送る前に断ります）。
- エージェント（MCP）が作れるのは、**Claude Code のセッションだけ**です。シェルや任意のコマンドのセッションは、作ることも、再開することも（`session_resume`・`profile_run` を含む）できず、人が作ったシェルにも入力できません（MCP を、確認なしでコマンドを実行する入口にしないため）。作業フォルダは、事業に登録したフォルダの中だけです（フォルダの登録はセットアップ担当もできますが、ホーム・ドライブの直下などは登録できません）。
- エージェントが書いた指示（`session_create` の最初の指示・エージェントが作ったプロファイル・`setup_agent_start`・エージェントが作ったプリセット〔人がボタンで送るときも〕）には、先頭に「【送信元：…】」が付きます。受け取ったセッションは、人の発言と区別できます。
- エージェントは、Hub の MCP のツールでは、**CLAUDE.md・安全に関わる設定・組織のルール・MCP の接続を、変えられません**（人が画面で行う）。
- MCP は `127.0.0.1` だけで待ち受け、合言葉（トークン）が必要です。ブラウザからの呼び出しは拒否します。
- アプリ内ブラウザは、ページからの権限の要求（カメラ・マイク・位置情報・通知など）を、既定で断ります。
- Hub の MCP のツール（フォルダの一覧・CLAUDE.md の確認と変更案）が扱えるのは、事業に登録したフォルダの中だけです。ドライブの直下・ホームフォルダとその親・`~\.claude`・Hub のデータのフォルダ・ネットワークの共有は、登録できません（ジャンクションなどのリンクは、たどった先で判定します）。（Claude Code そのものが読めるファイルは、Claude Code の権限の設定で決まります）
- Hub は、Claude Code の権限の設定を勝手に緩めません（`--dangerously-skip-permissions` は付けません）。

**これらの守りは、Claude Code の権限の確認が前提です。** 上の制限は、Hub の MCP のツールについてのものです。Claude Code そのものの道具（ファイルの読み書き・コマンドの実行）は、Claude Code の権限の設定で決まります。また、Hub の MCP のうち、ほかのセッションを動かすもの（`session_create`・`session_send`・`session_resume`・`profile_run`）と、ブラウザを動かすもの（`browser_*`）は、Claude Code の確認で「常に許可」にしないことを勧めます。ページに仕込まれた文（プロンプトインジェクション）から、ほかのセッションに指示が渡るのを防ぐためです。

設定の「CDP」（外部の Playwright などから Hub のブラウザを操作する）を有効にすると、合言葉のないデバッグ用のポート（`127.0.0.1:9333`）が開き、この PC のどのプログラムからも Hub の画面を操作できるようになります。既定はオフです。必要なときだけ有効にしてください。

くわしくは [CLAUDE.md](CLAUDE.md) の「弱めてはいけない安全の不変条件」。弱点を見つけたときは [SECURITY.md](SECURITY.md) の方法で知らせてください。

## 必要なもの
- Windows 10／11（x64）
- [Node.js](https://nodejs.org/) 22.12 以上
- [Claude Code](https://docs.claude.com/en/docs/claude-code)（`claude` コマンドが使え、ログイン済みであること）

## 使い方（ソースから）
```
git clone https://github.com/buildersloop/hub.git
cd hub
npm install
npm start
```
1. 最初は「はじめての事業」（見本）が 1 つだけあります。作業フォルダは `~\BuildersLoopHub\general` です。「🗂 事業の管理」で、名前と作業フォルダを、自分の事業に合わせて変えます。
2. 「📜 組織のルール」に、全セッションに守らせたいルールを書きます（任意）。
3. 「＋ 新規セッション」で Claude Code を起動します。Hub の MCP は、起動したセッションに自動で渡ります。
4. 設定は「⚙ セットアップ担当」に頼むこともできます。

**画面の操作**
- 端末の文字のコピー：ドラッグで選んで `Ctrl+C` か右クリック。Claude Code の画面全体の表示では、Claude Code 側で選んでコピーすると、そのままクリップボードに入ります。選べないときは、`Shift` を押しながらドラッグします。貼り付けは `Ctrl+V` か、何も選んでいないときの右クリック（シェルに改行を含む文を貼るときは、右クリックでも Ctrl+V でも、確かめます）。
- 左上の「☰」で、左の一覧をたためます。タブが多いときは、タブの列をホイールで横に動かせます（タブの左の色は、事業の色）。

exe にまとめる方法は [docs/RELEASING.md](docs/RELEASING.md)。

## いまの限界
- **Windows のユーザー名に、日本語や空白が入っている PC** では、Hub のデータのパスを、Claude Code に引数で渡せません。このとき、各セッションに自己紹介（名簿・組織のルール）と Hub の MCP が渡らず、画面にその旨を出します（セットアップ担当は、役割を最初の指示に入れて起動しますが、Hub の MCP のツールは使えません）。
  - 回避策：画面の「MCP」→「コマンドをコピー」で `claude mcp add`（利用者の設定）に登録すると、すべてのセッションで Hub の MCP が使えます。
- アプリ内ブラウザのログインと、MCP の接続の秘密の値は、新しい版に引き継がれません（入れ直しが要ります）。

## データの置き場
- `%APPDATA%\buildersloop-hub-v<n>\hub.json`：事業・セッション・設定（版ごとに別。新しい版は、初回に直前の版の設定を引き継ぎます）。
- 会話の記録は、Claude Code の通常の場所（`~\.claude\projects\…`）です。Hub は、その記録を読んで、共同作業の一覧を作ります。

## 設計メモ

### 版とデータの引き継ぎ
- 版（V8 など）ごとに、データの置き場と MCP のポート（17890＋版の番号）を分けています。新しい版を試しながら、古い版も動かせます。
- 新しい版を初めて起動すると、**直前の版**（無ければ、それより前の版）の `hub.json` をコピーします。元のデータは変えません。合言葉（トークン）とポートは、新しい版のものに作り直します。
- V7 までは、いつも最初の版（版のないデータ）からコピーしていたため、間の版で足した設定が引き継がれませんでした（V8 で修正）。

### 組織のルール
- 人が画面で書き、Hub が、各セッションの自己紹介（`--append-system-prompt-file`）・セットアップ担当の役割・CLAUDE.md の雛形に入れます。
- エージェントは読めますが、変えられません。自分を縛るルールを、エージェントが緩められないようにするためです。
- 以前は、持ち主のアカウント名をコードに直接書いていました。公開に向けて、設定に移しました（V8）。

### 既存の会話を Hub へ取り込む（session_adopt）
- `session_adopt`（MCP）：既存の Claude Code の会話（ID＝環境変数 `CLAUDE_CODE_SESSION_ID`）を、事業のセッションとして登録する。**起動はしない**。作業フォルダ（cwd）は、その会話を開始したフォルダ（記録 `.jsonl` の場所が、これで決まる）。
- 登録後、**元の会話（CLI）を終了してから**、Hub で「▶ 続きから再開」→ `claude --resume <同じ ID>` で、同じ会話を続けられる。**同じ記録に同時に書かないため、元の会話が動いている間は、起動しない。**
- `node test/hubctl.js <tool> '@ファイル.json'` ：引数をファイルから渡せる（シェルを通ると、バックスラッシュが壊れるため）。

### ログイン（Google・X など）への対応
- ブラウザの名乗りを、ふつうの Chrome にそろえる（`Electron/…`・アプリ名を含めない）。
- `window.open` のポップアップ（「Google でログイン」など）は、タブにせず、**同じログイン領域を共有する子ウィンドウ**で開く（`window.opener` で、元のページへ結果が返る）。
- 入力・撮影は、画面の描画に依存しない方式（CDP）を主にする。
- 限界：Google は、組み込みブラウザからのログインを、名乗り以外の手がかりでも、拒否することがある。その場合は、X はメールアドレス／パスワードでのログインを使う、または、Playwright MCP のブラウザ（別のログイン領域）を使う。
